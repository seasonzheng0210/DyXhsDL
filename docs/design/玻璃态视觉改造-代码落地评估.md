# 玻璃态视觉改造 — 代码落地评估

> 状态：评估完成（待用户裁定关键决策后立项）
> 日期：2026-09-06
> 关联：`docs/design/UIv2-软光玻璃定稿总览.html`（13 屏视觉总览，commit 7d65a93）

## 0. TL;DR（结论先行）

- **可行，且比预想便宜**：不必自绘 blur、不必换主题库。Miuix 0.9.2 的 `MiuixTheme(colors=…)` 支持整体注入自定义色板 → **改一套"玻璃色板"即可让全 App 背景/卡片/容器全部玻璃化**，无需逐组件重写。
- **真实毛玻璃（backdrop blur）在纯 Compose 里没有现成 API**（minSdk 24，RenderEffect 需 31+）。但本设计壁纸是**平滑渐变**，视觉上"无需 blur 也有磨砂感"；只有悬浮栏穿滚动文字那一种场景才真正需要 blur → 降级为可选 Phase-2，且仅 API 31+ 生效。
- **推荐路线**：根壁纸层（Canvas 渐变，零资源零模糊）+ 玻璃色板注入（亮/暗两套）+ 少量组件适配（页面大卡、删除红底、进度条、玻璃按钮高光描边）。估算：基线屏（任务列表）1 天级，全屏含回归 3–5 天。
- **必须先做一个设计裁定**（见 §7 决策点）：内容层卡片是"近实心微透明"而非全透明玻璃，否则列表滚动叠字、对比度崩塌。这是 iOS/HyperOS App 内一致做法，不是妥协。

## 1. 现状盘点（代码事实）

### 1.1 主题入口（杠杆点：只有 2 个）
- `MainActivity.kt:425` / `SettingsActivity.kt:258`：`MiuixTheme(controller = controller)`，`ThemeController(ColorSchemeMode.System)` → 明暗自适应 + Android 12+ 系统动态色(Monet)。
- Miuix 0.9.2 API 事实（解包 aar 核实）：
  - `MiuixTheme` 双重载：`(ThemeController, …)` 与 **`(Colors, …)`** → 可注入自定义色板。
  - `ColorsKt.lightColorScheme(...)/darkColorScheme(...)`：53 色角色，**带默认参数工厂**（`$default` 存在）→ 只需覆写要变的角色。
  - `Colors` 属性是 MutableState 委托 + 内部 setter（App 侧改实例属性不可行，须走工厂/覆写参数）。
  - **无任何 blur / 玻璃组件**：basic 包全为纯色组件；`TopAppBarDefaults/SearchBarDefaults` 无 blur 字段；`miuix-shader` 只有 RuntimeShader(AGSL，API 33+)，非 backdrop blur。
- 角色全景（glass 化相关）：`background / onBackground / onBackgroundVariant / surface / surfaceVariant / surfaceContainer(High/Highest) / onSurface* / dividerLine / windowDimming / primary* / secondaryContainer*` 等 53 色。

### 1.3 现状背景实现（无壁纸层）
- `values/styles.xml`：`statusBarColor/navigationBarColor/windowBackground` 均 **transparent**，沉浸式基础已就位。
- Compose 侧无壁纸概念：`HistoryPage` 主体 = 一张 `Card(fillMaxSize, surface)` 大卡；任务卡 = `surfaceVariant`；背景兜底 = Miuix `background` 纯色。
- **即：今天所有"容器"都是不透明纯色，"玻璃"要从零建立语义。**

## 2. 玻璃语义分层（本次评估最重要的设计裁定）

定稿视觉里"壁纸透过玻璃"，但**任务列表的内容本身就是内容**——内容层不可能全透明（滚动叠字/对比度崩塌/删除红底穿帮）。正确语义（iOS/HyperOS App 内一致）：

| 层 | 成员 | 玻璃策略 |
|---|---|---|
| **Chrome 层（真磨砂）** | 顶部大标题栏、底部主标签栏、搜索胶囊、分段控制器、进度胶囊、浮层(Sheet/Dialog 背景) | 高透磨砂：白 50–65% (暗 12–18%) + 壁纸渐变透出 → **观感最玻璃的地方** |
| **内容层（近实心微透）** | 任务卡、预览统计卡、范围卡、设置分组卡 | 白/浅 85–92% (暗 22–28%) + 1px 内顶高光 → 有玻璃质感但**不透下层文字** |
| **强调层（玻璃态橙）** | 主按钮、开关、进度条、推荐 pill | rgba(255,105,0,.82/.85/.8) + 顶内高光（令牌已定稿） |
| **壁纸层（最底）** | 全局 Canvas 渐变（米白/焦糖/鼠尾草/雾蓝 徕卡四色，暗色深版） | 固定不滚动；**渐变本身平滑=无需 blur 已具磨砂感** |

> 关键推论：由于壁纸是平滑色带，Chrome 层半透明白叠渐变即可得到干净玻璃观感——**真 blur 只对一种情况有意义：滚动内容（文字/缩略图）从悬浮玻璃底下穿过**。此场景只在底部主标签栏（浮层式时）出现，作为 Phase-2 可选补强（§4 路径 C）。

## 3. 技术路径对比

| 路径 | 做法 | 效果 | 成本 | 风险 | 结论 |
|---|---|---|---|---|---|
| **A. 色板注入（推荐）** | `MiuixTheme(colors = GlassColors.light/dark())` 覆写 background/surface/surfaceVariant/surfaceContainer* 为半透明白/浅 + 根层垫 Canvas 渐变壁纸 | 全 App 容器/背景统一玻璃化，令牌集中一处 | 低（主题×2 入口 + 令牌文件 + 壁纸层 1 处） | 低：半透明叠加副作用需逐屏走查（§6） | **首选** |
| B. 逐组件自绘 GlassCard | 自写 GlCard/GlSurface 替换 18+ 处 Card | 每处可调 | 高（36+ 引用全动） | 中（易漏、风格漂移） | 仅 A 覆盖不到的特殊件用 |
| C. 真 backdrop blur（Phase-2 可选） | 悬浮栏区域 RenderEffect/离屏合成；minSdk 24 → **API≥31 生效、<31 自动降级 A 观感** | 内容穿玻璃被磨砂（iOS 级） | 高（无 Compose 原生 API，需自研或 View 混排） | 高 | 基线版不做；仅"底部悬浮栏"若穿帮再补 PoC |
| D. RuntimeShader(AGSL) | miuix-shader 已带 RuntimeShader | 动态壁纸等花活 | 高（API 33+） | 高（降级面大） | **弃**（非 backdrop blur，收益不匹配） |

## 4. 推荐方案落地设计

### 4.1 新增文件
1. **`ui/glass/GlassTokens.kt`** — 定稿令牌落地（值来自 UIv2 总览）：
   ```kotlin
   object Glass {
     // 壁纸（Canvas 渐变三/四点）
     val WallpaperLight = listOf(0xFFF4E7D6, 0xFFE0A06B, 0xFFBFD0C6, 0xFFB2CCDC)
     val WallpaperDark   = listOf(0xFF2A2320, 0xFF3A2E24, 0xFF2C3431, 0xFF27343D)
     // Chrome / 内容层玻璃（亮）
     val ChromeLight   = 0xB3FFFFFF  // 白 70%（≈50%+渐变提亮）
     val ContentLight  = 0xE6FFFFFF  // 白 90%
     // （暗）ChromeDark = 白 12–18% 等 —— 全套见实现
     // 玻璃态橙（已定稿）
     val OrangeGlass      = Color(0xFFFF6900).copy(alpha = 0.82f)
     val OrangeGlassDeep  = 0xFFE05A00  // 文字级橙
   }
   ```
2. **`ui/glass/GlassColorSchemes.kt`** — `GlassColorScheme.light()/dark()`：基于 `lightColorScheme()/darkColorScheme()` **只覆写背景族**（background/surface/surfaceVariant/surfaceContainer*/dividerLine…）+ 橙主色，其余沿用 Miuix 默认值（53 参默认工厂）。返回 `Colors`。
3. **`ui/glass/WallpaperLayer.kt`** — `@Composable fun WallpaperLayer(modifier)`：`drawBehind` Canvas 对角渐变（light/dark 按系统），铺 `fillMaxSize` 最底层。
4. **`ui/glass/GlassShape.kt`**（可选首屏做）— 顶高光/描边扩展：`Modifier.glassTopHighlight()`（1px 内描边白 90%/暗 16%），供大按钮/大卡等强调件使用。

### 4.2 改动点（最小集）
| 文件 | 改动 |
|---|---|
| `MainActivity.kt` / `SettingsActivity.kt` | ① `MiuixTheme(controller=…)` → 按 `isSystemInDarkTheme()` 选 `MiuixTheme(colors=GlassColorScheme.light()/dark(), …)`；② 根 `Box` 最底层插 `WallpaperLayer()`。（**放弃 Monet 跟随**——本来就要锁品牌橙，须用户认可，§7） |
| `MainActivity.kt` HistoryPage 外层大 Card | surface → Content 玻璃色（或不透明 92%）——**决定壁纸可见性的关键一改** |
| 任务卡/卡片组 | 依赖主题色已自动玻璃化；删除红底 `F44336` 若穿帮改放玻璃卡之上或加深（§6-1） |
| Button/进度/开关 | 已定稿玻璃橙令牌：需查 ButtonDefaults 颜色是否走 primary → 覆写 primary 即全局生效；特殊件走 GlassShape |

### 4.3 为什么"不逐组件也能全 App 生效"
- 组件（Card/Surface/Button/TextField/Dialog）的颜色**全部经 `MiuixTheme.colorScheme` 角色取色**（44+6+… 处引用全是角色，不是硬编码十六进制）→ 换色板 = 换全部。硬编码色（删除红、源标签抖音青/小红书红/快手橙 badge、进度色）另列清单逐个裁决。

## 6. 风险清单（半透明引入的副作用，逐条要有对策）

1. **删除红底穿帮**：任务卡半透明后，下层 `F44336` 删除条会透出 → 对策：玻璃卡不透删除层（卡背景在删除条之上绘制不透明底，或删除红移入卡内层）。
2. **Dialog 叠 Sheet 叠列表**：多层半透明叠加 → 可能过白/过脏 → 对策：弹层背景给更高不透明度（92%+）或 dim 层补偿。
3. **滚动叠字**：内容卡微透 90% 仍可能见下层大字号 → 对策：90%+ 起步，逐屏调，永不 <85%（内容层底线）。
4. **暗色模式**：白 12% 玻璃 + 深渐变壁纸 → 文字对比需走查（onSurface 白 87% 起步）。
5. **性能**：零实时 blur 版 = 普通半透明合成，无额外成本；P3 blur 仅悬浮栏局部、单层 RenderEffect，须 frame 实测。
6. **Monet 动态色弃用**：用户换系统壁纸后 App 颜色不再漂移（锁品牌橙）——是特性，但改变现状行为，需认可。
7. **Compose 预览/截图**：Canvas 渐变在 Preview 正常；壁纸如改资源图则需 nodpi 双暗色。
