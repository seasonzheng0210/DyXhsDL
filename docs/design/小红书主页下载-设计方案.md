# 小红书主页下载 · 设计方案

> 2026-10-21 · 基于现有抖音主页下载 v2 架构（入口→预览→批量）设计，目标：小红书作者主页批量下载，交互与抖音完全对齐。
> 技术底座已验证：`BgWebViewParser` 的「嗅探页面自身请求」路线在小红书同样必要——小红书 Web 接口（`x-s`/`x-t`/`x-s-common`）签名只能由页面 xhs.js 产出，纯 HTTP 自建请求必被拒，与抖音 `uifid`/`verifyFp` 同理（见主页下载-全局重构方案-v3 §1.6/§1.8）。

---

## 0. 结论先行

1. **架构完全复用抖音主页下载三步流**：统一入口 `openHomepage()` → 预览（S2/S3/S4）→ 批量下载。新增的只是解析层。
2. **与抖音的一个关键差异**：小红书列表接口（`user_posted`）**不带媒体直链**（抖音 post 接口列表自带 play_addr），必须逐条取详情 → 多一层「逐条解析」，也是本方案的主要成本。
3. **好消息**：逐条详情不用写新链——加载 `/explore/{note_id}?xsec_token=…` 页面后的媒体提取逻辑（`imageList[].url_default` / `video.media.videoStream[].masterUrl`）与现有 `XHSDownloader.java` 单作品链**完全一致**，可整体复用。
4. **预览体验不受影响**：列表响应自带 `cover`（封面图）+ `display_title` + `type`，不逐条解析就能渲染完整预览页，与抖音一致。
5. 分期：P0 最小可用（列表嗅探首屏 + 逐条下载）；P1 登录态 + 分页 + 批量提速；P2 稳态加固。

## 1. 现状盘点

| 项 | 抖音（已上线） | 小红书（现状） |
|---|---|---|
| 主页入口 | `openHomepage()` 统一通道（6 种来源） | 无；`user/profile` 链接走单作品链会失败 |
| 列表获取 | `sniffHomepage()` 嗅 `/aweme/v1/web/aweme/post/`，**列表带直链** | 无 |
| 预览 | S2 下载计划卡 + S3 HomePlanSheet + S4 Picker（封面/标题/数量档） | 无 |
| 批量下载 | v2 直链批量（HomepageBatchStore + HomeRepo 账本） | 无 |
| 单作品 | DouyinParser 六候选 + WebView 兜底 | XHSDownloader（WebView 抓 `__INITIAL_STATE__`，已支持 imageList/masterUrl/h265） |
| 作者回跳 | 任务详情 AuthorHomeEntryCard（**明确排除小红书**） | 排除 |

## 2. 技术方案

### 2.1 解析链（两层嗅探）

```
入口链接（user/profile/{userId} 或 xhslink 短链 302 落地）
   │
   ▼
L2x-1 · 列表嗅探  sniffXhsHomepage(userId)
   加载 xiaohongshu.com/user/profile/{userId}
   hook fetch/XHR，嗅页面自己发出的：
   GET /api/sns/web/v1/user_posted?num=30&cursor=…&user_id=…&image_formats=jpg
   响应 data.notes[] → { noteId, xsecToken, title=display_title,
                         type=video|normal, cover.url_pre?url }
   页面自动滚动可触发 cursor 翻页 → 逐页累积去重
   （profile 接口 /api/sns/web/v1/user/populishtab? 或 user/other 提供 nickname）
   │
   ▼
预览页（列表数据即可渲染，零额外请求）
   │  用户确认范围/数量
   ▼
L2x-2 · 逐条详情  复用 XHSDownloader 单作品链
   逐条加载 /explore/{noteId}?xsec_token={token}&xsec_source=pc_user
   → __INITIAL_STATE__ → imageList[].url_default（去 ?x-oss-process= 原图）
                        / video.media.videoStream h264[].masterUrl（无水印）
   串行 + 间隔 2~4s + 随机抖动
```

### 2.2 与抖音嗅探的差异点（实现时必须处理）

| 差异 | 抖音 | 小红书 | 对策 |
|---|---|---|---|
| 列表带直链 | ✓（post 带 play_addr） | ✗（只有 cover/标题） | 多一层逐条详情（复用单作品链） |
| 分页方式 | 接口内游标 + 页面加载更多 | `cursor` 参数 + 页面滚动触发 | 嗅探层累积多页响应，按 note_id 去重 |
| 通行证 | uifid/verifyFp 由 secsdk 产出 | **`xsec_token` 每条笔记一个**，由列表响应下发，过期失效 | 逐条 URL 必须携带对应 token；token 失效 → 重嗅列表刷新 |
| 环境身份 | DESKTOP_ENV_ASSET（platform=Win32 交叉校验坑） | 小红书 UA/平台校验较松，**移动 UA 即可**（XHSDownloader 现用 Android UA 已验证可行） | 不需要抖音那套环境注入 |
| 未登录上限 | 首屏 21 条 | 待实测（预计首屏 ~30 条，滚动加载可能要求登录） | P0 只做首屏；P1 加登录引导 |
| 档案接口 | `user/profile/other` 给 aweme_count | 列表响应 `data.total`?（待实测；无则不显示总数） | totalCount 可缺省，预览显示「已获取 N 条」 |

### 2.3 媒体提取（复用现有代码）

- **图文**：`note.imageList[].url_default`——小红书 CDN 图片去掉 `?x-oss-process=style/xxx` 后缀即无水印原图（`XHSDownloader.java` L889 已有解析）。
- **视频**：`note.video.media.videoStream[]` 取 `h264[0].masterUrl`（L1213 已有，h265 作为 fallback）。
- **Live Photo**：图文笔记若含 `livePhoto` 字段（图+短视频对），P1 对齐抖音的「创建安卓动态照片」开关。

### 2.4 风控与对策

| 风险 | 症状 | 对策 |
|---|---|---|
| 逐条请求频率过高 | 461 / 验证码 | 串行 + 2~4s 随机间隔；单批默认 ≤30 条；失败退避 |
| `xsec_token` 过期 | 单条 404/风控页 | 重嗅列表刷新 token 后重试该条（最多 1 次） |
| 未登录上限 | 列表只有首屏 | P0 明示「已获取首屏 N 条」；P1 WebView 登录引导（登录一次持久 cookie） |
| 页面改版 | 嗅探零命中 | 复用 `onHomepageSniffLog` 诊断日志流 + `lastFailReason()` 失败归因 |

## 3. 交互设计（对齐抖音，只列差异）

1. **入口①（主）**：首页下载承载面粘贴 `xiaohongshu.com/user/profile/…`（含 xhslink 短链 302 落地）→ `fetchHomepagePreview` 增加平台路由 → 三阶段进度条文案复用（阶段 0「定位作者主页」对小红书直接跳过）。
2. **入口②**：任务详情「下载该作者的主页」卡解锁小红书 —— 前提：小红书单作品解析时落 `authorId` 到 `DownloadTask.authorSecUid`（现仅抖音/快手）。
3. **预览页（S2/S4）**：与抖音同构——封面网格（cover 图）+ 类型徽标（图文/视频）+ 数量档 + 两开关（去水印天然支持）；顶部显示「已获取首屏 30 条」或登录引导条。
4. **确认后**：任务卡 source=`xhs_home`，文案「主页批量 · N 个作品」；进度按作品数（不是文件数）汇报，单作品内部再报文件级进度。
5. **批量执行**：P0 串行逐条「解析→下载」，任务 reason 带每条结果；单条失败不中断整批（对齐抖音 v2 语义）。

## 5. 分期

- **P0 · 最小可用**（预计 2~3 个工作日）：入口① + 列表嗅探（首屏，不滚动分页）+ 预览选择 + 逐条解析下载（复用单作品链）。验收：任意公开小红书主页 → 首屏作品批量下载成功。
- **P1 · 完整体验**：滚动加载更多页；WebView 登录引导（登录后解锁全部作品）；入口②（E7 解锁 + authorId 落库）；Live Photo 对齐。
- **P2 · 稳态加固**：feed 接口批量嗅探（替代逐条开页，提速）；失败重试面板；频率自适应（461 自动退避拉长间隔）。

## 6. 待实测清单（P0 开工前 1 天用 CDP/WebView 验证）

1. 未登录 `user_posted` 是否真的只给首屏、`data.total` 是否存在。
2. `xsec_token` 在列表响应的确切字段名与位置（历史版本在 `notes[].xsec_token`）。
3. 移动 UA 下页面是否自动发出 `user_posted`（小红书可能对移动 WebView 给 H5 版页面，接口路径不同——若是，改嗅 H5 对应接口或注入 DESKTOP_ENV 同款平台伪装）。
4. 逐条 explore 页在 WebView 中直接加载（无 referrer）是否正常返回 INITIAL_STATE。

> 以上任何一条与预期不符，只影响 §2.1 的嗅探细节，不动整体架构。
