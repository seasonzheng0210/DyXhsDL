# 主页批量下载功能设计（v2）

> 版本：2026-09-05 初稿 · 状态：待拍板
> 前置基建：v1.12.0 DouyinAbogus（纯 Kotlin a_bogus）+ CookieManager 预热 + v1.14.x 主页批量任务卡（MODE_DOUYIN_HOME）

---

## 1. 背景与痛点

现主页下载链路：输入主页链接 → **可见** WebViewActivity 打开作者主页 → 自动滚动收集 `/video/{id}` 链接（最多 40 轮 × 1.2s）→ 回传 Service 逐条解析下载。

实测暴露的问题：

| # | 问题 | 根因 |
|---|------|------|
| 1 | 匿名/未登录直接 0 收集 | 抖音主页对匿名会话弹登录墙，滚动爬取必须有可见页面+登录态 |
| 2 | 大主页收集不全 | 40 轮上限 ≈ 48s，且「连续 5 轮无新增」即判定到底，懒加载稍慢就提前截断 |
| 3 | 慢 | 逐条解析：HTTP 快解(10s) → Cookie 预热(15s) → WebView 兜底(60s)，每条最坏 ~85s |
| 4 | 重复下载 | 无作品级去重，追更场景全量重下 |
| 5 | 只支持抖音 | 快手/小红书主页无入口 |
| 6 | 盲下 | 收集完直接开下，不告知作者/作品数，不可选范围 |

## 2. 设计目标

1. **一条主页链接 → 全量/增量批量下载**，全程无可见页面（登录态已有时）。
2. **快**：列表阶段一次拿齐全部作品直链，下载并发执行，20 条作品 ≤ 5 分钟。
3. **去重 + 追更**：作品 id 级记录，「追更」模式只下新作品。
4. **可预览再下**：先展示作者昵称/作品数，选范围（全部 / 最新 N 条 / 追更）再确认。
5. 平台分阶段：抖音 → 快手 → 小红书。

非目标（本期不做）：逐条作品勾选 UI、评论/封面下载、私密账号（明确提示不支持）。

## 3. 核心方案选型

### 3.1 作品列表获取（关键决策）

| 方案 | 说明 | 成功率 | 复杂度 | 结论 |
|------|------|--------|--------|------|
| A. 可见 WebView 滚动爬取（现状） | 需登录态+可见页，48s 上限 | 中（登录墙拦截） | 已有 | 降级为人工兜底 |
| B. **Web post API 直取（推荐主路径）** | `GET /aweme/v1/web/web/aweme/post/?sec_user_id=&count=18&max_cursor=` + a_bogus + CookieManager cookie，HTTP 翻页 | 高（同 detail API，已实证可过 Argus） | 低——**完全复用 v1.12.0 基建** | ✅ P1 主路径 |
| C. 后台离屏 WebView 爬取 | BgWebViewParser 扩展 homepage 模式，离屏滚动收集 | 中高 | 中 | ✅ 作 B 的风控兜底 |

**选 B 为主、C 兜底、A 人工兜底的三级降级**。理由：

- B 复用现成的 `DouyinAbogus.buildQuery/getValue` + `SIGN_UA` + CookieManager 预热，新增代码量最小；且**列表响应里自带每条作品的 play_addr/images/desc**——直链一次拿齐，省掉逐条 detail 请求，这是提速的根本。
- C 复用离屏 WebView + Mutex 串行，把现有 `crawlHomepage` 的滚动收集 JS 抽成 asset，在后台跑。
- A 保留现有 WebViewActivity homepage 模式，仅在前两级都失败时引导用户登录/手动确认。

### 3.2 单条作品下载

- 列表阶段已得直链 → 直接进现有 FileDownloader（视频 `play_addr` 去水印、图集 `images[]` 逐张）。
- 直链 403/失效 → 单条走现有 `resolveDouyinMediaInfo`（HTTP→预热→WebView）重解析兜底。
- aweme_type 判别图文帖，复用 `downloadImages`（v1.10.9 的 note 图集提取经验：列表接口 images[] 结构与 detail 一致）。

## 4. 架构与数据流

```
输入主页链接（短链 / /user/{sec_uid} / 视频反查）
        │  UrlUtils 归一化 → sec_uid
        ▼
┌─ 主页解析编排（DownloadService 新 MODE_HOMEPAGE，兼容旧 MODE_DOUYIN_HOME）─┐
│  L1 DouyinPostListApi.fetchPostList(secUid)      ← HTTP + a_bogus + cookie  │
│     └ 403/风控 → warmupAndSnapshot 预热 → 重试 1 次                          │
│  L2 BgWebViewParser.crawlHomepageBg(userUrl)     ← 离屏滚动收集（兜底）       │
│  L3 WebViewActivity homepage 模式               ← 可见人工兜底（登录引导）    │
└──────────────────────────────────────────────────────────────────────────┘
        │  作品列表 [aweme_id, type, desc, 直链/images] ×N 页
        ▼
   过滤：HomeRepo 已下载 id 去重（全部模式跳过；追更模式只留新）
        ▼
   预览确认（UI）：作者昵称 · 作品总数 · 新增数 · 范围选择 → 确认下载
        ▼
   并发下载（Semaphore 2）：视频 FileDownloader / 图集 downloadImages
        │  单条直链失效 → resolveDouyinMediaInfo 重解析
        ▼
   任务卡终态（成功/部分失败/全部失败）+ HomeRepo 落账
```

新增/改动组件：

| 组件 | 改动 |
|------|------|
| `DouyinParser`（或新 `DouyinPostListApi`） | 新增 `fetchPostList(secUid, cursor): PostPage`，复用 DouyinAbogus + cookie 快照 + `WebDetailBlockedException` 语义 |
| `BgWebViewParser` | 新增 `crawlHomepageBg(userUrl, maxMs): List<String>`：离屏加载主页 → 注入 `homepage_collector.js`（从 crawlHomepage 抽出）滚动收集 |
| `DownloadService` | 新 `MODE_HOMEPAGE` 编排（列表→过滤→并发下载），旧 `MODE_DOUYIN_HOME` 逻辑并入兼容 |
| `HomeRepo`（新，P1 用 JSON 文件） | `files/home_index.json`：`{sec_uid: {nickname, downloaded_ids:Set, last_sync}}`；作品级去重与追更依据 |
| `MainActivity` 主页 tab | 两段式 UI：①输入/粘贴 → ②预览卡（昵称/总数/新增/范围选择：全部·最新 N·追更）→ 确认开任务 |
| strings 三语言 | 预览卡与范围选择文案 |

## 5. 关键细节

- **去重键**：aweme_id（作品级），不依赖文件名。下载成功才算入账；失败条下次「重试任务」只跑失败集。
- **并发**：Semaphore(2) 串两路下载，避免触发 CDN 限速；WebView 兜底仍全局 Mutex 串行。
- **进度**：任务卡 totalFiles=作品数，`updateProgress` 按条驱动（复用主页批量现有实现）；图集多图算 1 条。
- **取消**：尊重任务取消（`myJob.isActive`），已下条目不回滚。
- **快手（P2）**：`www.kuaishou.com/profile/{userId}` 桌面页 `__APOLLO_STATE__` / GraphQL `visionProfilePhotoList` 翻页，复用 KuaishouParser 的 GraphQL 客户端；列表同样带 photoUrl 直链。
- **小红书（P3）**：user 页 `__INITIAL_STATE__` 拿笔记卡片，风控最强、无签名基建，放最后。

## 6. 阶段计划

| 阶段 | 内容 | 验收标准 |
|------|------|----------|
| **P1 抖音全量** | post API 列表 + 预览确认 UI + 并发下载 + 去重/追更 + 失败重试 | 真机登录态下：100 作品级主页收集率 ≥95%；20 条 ≤5 分钟；追更第二次运行 0 重复下载 |
| **P2 快手 + 兜底** | 快手主页列表 + L2 离屏爬取兜底 + 登录引导统一化 | 快手真实主页全量可下；抖音 post API 被风控时自动降级 L2 成功 |
| **P3 小红书 + 勾选** | 小红书主页；作品列表勾选 UI（如有需求） | 小红书主页可下 |

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| post API 概率性 403（Argus，同 detail） | warmup 重试 → L2 离屏爬取 → L3 人工，三级降级不断链 |
| a_bogus 算法被抖音更新 | DouyinAbogus 已有 Python 金标准单测，失效时升级签名实现 |
| 列表直链带时效签名过期 | 失效单条走 resolveDouyinMediaInfo 重解析，不做全量重拉 |
| 主页含图文/置顶/直播回放混杂 | 按 aweme_type 分流：图文走 images[]；直播回放跳过并计数提示 |
| 私密账号 / 作品 0 | 明确提示，不算失败 |

## 8. 需要拍板的点

1. **范围选择粒度**：P1 做「全部 / 最新 N 条 / 追更」三档够不够？逐条勾选放 P3 还是现在就要？
2. **默认行为**：粘贴主页链接后是「先预览再确认」（推荐，防误触全量）还是「直接开下」？
3. **快手/小红书优先级**：P2/P3 顺序是否认可？
