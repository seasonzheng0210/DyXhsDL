# 首页下载 · 交互重构方案

> 版本：2026-10-10 · 状态：待拍板
> 触发：用户报「关于首页下载这个功能 交互设计需要重构」
> 前身：`主页下载-全局重构方案-v3.md`（那份解决的是**能不能用**，本文档解决的是**好不好用**）
> 配套 mockup：`首页下载-交互重构-mockup.html`（可直接打开，右上角切亮/暗）

---

## 0. 结论先行

现在的首页下载**功能已可用**（v3.0.12 打通），但交互把「配置」「内容」「主操作」三层揉进了同一条滚动流，导致：

| 症状 | 我实测到的原始表现 |
|---|---|
| **主按钮找不到** | 模拟器上必须从底部上滑 **5 次**才滚到「确认下载」 |
| **面板内部自相矛盾** | 「包含图文 / 自动跳过已下载」两个开关在「按勾选下载」档下**被静默忽略**（代码里写了注释），用户改了没反应 |
| **选择语义打架** | 点一下网格，程序偷偷把档位切到「按勾选下载」，但没有任何视觉提示 → 用户以为「我明明选的是仅新增」 |
| **长任务无反馈** | 解析实测 **11~14 秒**，全程只有一行灰字「解析中…」，且**无法取消** |
| **硬约束事后才解释** | 253 条作品只给 21 条，然后用一行 11sp 灰字解释——这正是本次报障的心理起点 |
| **回访路径很长** | 「上次解析」卡只在 Idle 态出现，要先退出预览才看得到；而回访同一博主是这功能的高频用法 |

**重构主张（一句话）**：把主页页从「一条长表单」改成「**一个常驻操作条 + 三层状态**」——
解析结果只做**摘要与确认**，真正的挑选下沉到二级页，主按钮永远不动。

## 1. 根因分析（不是罗列现象）

| # | 根因 | 为什么是根因 | 对应设计原则 |
|---|---|---|---|
| R1 | **主操作被放进滚动流** | `确认下载` 是 `HomepagePage` 里 `Column.verticalScroll` 的**最后一个子节点**。内容越长（60 条网格），它越远。且它与内容之间还夹着范围卡、开关卡，视线要来回跳。 | **P1 主操作脱离滚动流** |
| R2 | **两种选择语义压进同一个单选列表** | `全部作品 / 仅新增 / 按勾选下载 / 最近N条` 里，前两个和第四个是**策略**（按规则选），第三个是**枚举**（明确指定）。混在一起 → 互斥关系说不清，且开关对枚举档失效。 | **P2 策略与枚举分层** |
| R3 | **长任务零信息量** | 11~14s 是页加载 + SPA 水合 + post/profile 两个接口的真实耗时。一个转圈无法解释这段时间在干什么，用户会重复点击 → 并发请求。 | **P3 长任务要有阶段与出口** |
| R4 | **硬约束是事后解释** | 用户复制一个 253 条作品的博主，默认预期「全下」。拿到 21 条再看解释，第一反应是「坏了」而不是「哦要登录」。 | **P4 约束前置到计划里** |
| R5 | **回访场景没被当成主场景** | `HomeRepo.lastUsed` 已存在，但只在 Idle 态渲染一张卡。要换博主必须退出预览。 | **P5 回访路径要短** |

## 2. 新交互：状态机

```
        粘贴/自动填充
  Idle ──────────────► Parsing ──成功──► Ready ──确认──► Downloading ──完成──► Done
   ▲                     │                 │  ▲                                    │
   │                     │取消/失败         │  │  选片页返回（回写选中集）            │
   └─────────────────────┘                 ▼  │                                    │
                                       Picker ┘                                    │
   ◄─────────────────────── 再检查 / 换作者 ◄──────────────────────────────────────┘
```

**关键点**：`Ready` 是唯一的枢纽态。所有配置改动（调整面板、选片页）都回到 `Ready`，由底部的常驻操作条统一反映「将下载 N 个」。

## 3. 页面结构：常驻操作条

### 3.1 结构

```
┌──────────────────────────────────────┐
│ 抖快红下载                            │  顶栏（不变）
├──────────────────────────────────────┤
│                                      │
│   ┌ 滚动流：只放「内容」 ┐             │
│   │  · 作者摘要        │             │
│   │  · 下载计划卡      │             │
│   │  · 作品预览        │             │
│   └───────────────────┘             │
│                                      │
├──────────────────────────────────────┤
│ 将下载 18 个          [  开始下载  ]  │  ← 常驻操作条（sticky，不随滚动）
├──────────────────────────────────────┤
│  首页下载 |  任务  |  设置            │  dock（不变）
└──────────────────────────────────────┘
```

**规则**：滚动流只承载**阅读性内容**；任何「改变即将发生的事」的控件都走 **bottom sheet**；任何「推进流程」的按钮都进 **常驻操作条**。

### 3.2 常驻操作条的状态矩阵

| 状态 | 左侧文案 | 右侧主按钮 | 可点 |
|---|---|---|---|
| Idle | （不显示操作条） | — | — |
| Parsing | `正在解析…` | `取消` | ✓ |
| Ready（策略=仅新增） | `将下载 18 个 · 跳过 3 个` | `开始下载` | ✓ |
| Ready（手选 12 个） | `已选 12 个` | `下载已选` | ✓ |
| Ready（新增 0 个） | `没有新作品` | `开始下载`（禁用） | ✗ |
| Downloading | `下载中 12 / 18` | `去任务页` | ✓ |
| Done | `完成 17 个 · 失败 1 个` | `查看任务` | ✓ |

> 「没有新作品」时主按钮**禁用但保留**，而不是消失——位置稳定比省空间重要（避免按钮忽隐忽现导致误触）。

## 4. 六个屏幕

### S0 · 空态

- 单行输入框，**粘贴按钮内嵌为右侧图标**（省掉一整行，也省掉一次点击）
- 一个主按钮「解析主页」，去掉并列的次按钮
- **最近作者**横滑卡组（头像首字 + 昵称 + 「上次 21 条」）——点即重新解析
- 底部帮助文案折叠为一行 `ⓘ 支持主页分享文案 / user/xxx`，点击展开

### S1 · 解析中（11~14s）

分阶段 checklist，**阶段由真实回调驱动**（非假动画）：

| 阶段 | 触发时机 |
|---|---|
| `打开作者主页` | `loadUrl` 前 |
| `建立会话指纹` | 注入 `douyin_desktop_env.js` + `douyin_home_sniff.js` 完成 |
| `读取作品列表` | 嗅到 `post` 或 `profile` 响应 |

- 当前阶段高亮 + 转圈，已完成阶段打勾，未开始置灰
- 一行小字 `首次解析约需 10 秒`
- 输入框切换为**锁定态**（显示已解析链接 + 右侧 ✕），✕ 即取消

### S2 · 就绪（核心屏）

```
(奶) 奶霜莓莓                          ✕     ← 输入框位置切换为作者条
共 253 条作品 · 本次可取 21 条
⚠ 匿名上限，登录后可下载更多            →     ← 约束 + 出口
────────────────────────────────────────
下载计划                        [调整]        ← 打开 bottom sheet
  新增作品                          18
  跳过已下载                         3
  手动挑选作品                       →        ← 进 S4 选片页
────────────────────────────────────────
作品预览                  查看全部 21 条 →
[缩略图 ×6]
```

设计要点：
- **作者条占据输入框原位**——同一位置切换形态，减少页面跳变；✕ 即回到 Idle
- **约束前置**：「共 253 条 · 本次可取 21 条」放在昵称正下方，最显眼的位置
- **「下载计划」是摘要不是表单**：只读地展示三条人话结论，改设置去 sheet
- 预览只给 6 张缩略图（不是 60 条网格）——它是**确认信号**，不是挑选工具

### S3 · 调整面板（bottom sheet）

- 范围三选一：`仅新增（推荐）` / `全部作品` / `最近 N 条`（配 − / + 步进）
- 开关：`包含图文作品` / `跳过已下载`
- 底部一行注解：`ⓘ 手动挑选作品时本面板不生效`——**把 R2 的静默失效变成显式声明**
- 关闭按钮「完成」

### S4 · 选片页（二级）

- 顶部分段：`全部 21` / `新增 18` / `已下载 3`
- 类型筛选：`视频 21` · `图集 2`
- 右上「全选 / 反选 / 只选新增」
- 大格 3 列（4:5），角标显示 `▶ 时长` / `▣ 图集 N 张`；已下载加半透明遮罩 + `已下` 角标
- 常驻操作条：`已选 12 个` + `下载已选`
- 返回时不丢选择，回写 S2

### S5 · 下载中 / 完成

- 进度卡：`正在下载 12 / 18` + 进度条 + `成功 11 · 失败 1`
- 次级动作：`去任务页看细节` / `取消剩余`
- 完成：`✓ 下载完成 17 个（1 个失败）` + `查看任务` / `再检查新作品`

## 5. 落地改造点（对代码的具体影响）

| # | 现状 | 新设计 | 改造位置 |
|---|---|---|---|
| 1 | 确认下载在 `Column.verticalScroll` 末尾 | 移到 `Scaffold` 的常驻操作条 | `HomepagePage` 拆为 `HomepageContent` + `HomepageActionBar`；`MainActivity` 的 `Scaffold` 增条件 `bottomBar`（需垫在 dock 之上：`bottom = dock 高度 + navigationBars`，现已有 `96.dp + insets` 的算法可复用） |
| 2 | 4 档单选 + 2 开关平铺在页面里 | 摘要卡 + `ModalBottomSheet` | 新增 `HomepagePlanSheet`；`selectedRange / limitN / includeImages / skipDownloaded` 状态移入 sheet 托管 |
| 3 | 网格内联（前 60 条 + 展开全部） | 摘要预览 6 张 + 全高选片页 | 新增 `HomepagePickerPage`（建议用全高 `ModalBottomSheet`，避免新增 Activity + Manifest 注册） |
| 4 | `HomePreviewState.Loading` 是 `data object` | 需带阶段 | 改 `data class Loading(val stage: Stage)`；`BgWebViewParser.sniffHomepage` 增加 `onStage: (Stage) -> Unit` 回调，在 `loadUrl 前 / 注入完成 / 收到 post 或 profile 响应` 三处上报 |
| 5 | 解析不可取消 | 可取消 | `sniffHomepage` 需要 `cancellable` 支持：现有 `suspendCancellableCoroutine` + `cont.invokeOnCancellation` 里补 `finish()` 与 `stopLoading()` |
| 6 | 匿名上限是 11sp 灰字事后解释 | 摘要区「共 N · 可取 M」+ 登录入口 | 复用 `totalCount`；登录入口 = 用现有 `WebViewActivity` 打开抖音登录页 |
| 7 | `HomeRepo.recentAuthor()` 单条 | 需要多条 | `HomeRepo` 加 `recentAuthors(limit)`，基于已有 `lastUsed` |
| 8 | 网格默认勾选=全部新增 | 保持（语义已对） | `scopeHomepageItems` 不动 |

**不做破坏性改动**：`HomepageBatchStore.Range` 四档枚举全部保留（`ONLY_NEW/ALL/LATEST_N/SELECTED`），只是把前三档收进 sheet、第四档由选片页驱动。`DownloadService` 侧无需改动。

## 6. 权衡与取舍

| 决策 | 取 | 舍 | 理由 |
|---|---|---|---|
| 主操作条常驻 | 位置稳定性 | 约 72px 垂直空间 | 主按钮找不到是**阻断性**问题；空间是可让渡的 |
| 网格下沉二级页 | 首屏干净、主路径短 | 挑作品的用户多一次跳转 | 挑作品是**少数场景**；把少数场景的成本转嫁给主线不合理 |
| 粘贴按钮内嵌 | 少一行、少一次点击 | 图标可发现性略降 | 输入框为空时禁用态图标本身就是提示 |
| 范围收进 sheet | 面板内不再自相矛盾 | 调整多一次点击 | 默认值（仅新增+跳过已下+含图文）已是 90% 场景的最优解 |
| 选片页用全高 sheet | 不改 Manifest、动效自然 | 需处理 sheet 内嵌套滚动 | 新 Activity 要额外处理返回栈与状态回传，成本更高 |

## 7. 验收口径

| 项 | 标准 |
|---|---|
| 主路径步数 | 粘贴 → 解析 → 开始下载 = **3 步**，**0 次滚动** |
| 主按钮可见性 | 任何状态、任何滚动位置下，主按钮**始终可见** |
| 解析反馈 | 三个阶段真实上报；任意时刻可取消，取消后 ≤1s 回到 Idle |
| 约束传达 | 解析完成 1 屏内可见「共 N 条 · 可取 M 条」，无需滚动 |
| 回访 | Idle 与 Ready 两态均可一键切换到最近作者 |
| 面板一致性 | 不存在「改了没反应」的控件：被忽略的组合必须有显式说明 |
